# CNPAF Collect 功能基线 V5

> 目标：先保证业务闭环完整、角色可用、配置端与采集端一致，再扩展高级能力。

## 1. 本轮确认的核心问题

当前系统不是完全没有 Location、Task 或动态表单能力，而是相关能力没有被连成一条可用的业务链。

| 模块 | 当前状态 | 业务断点 |
| --- | --- | --- |
| 任务 | 已有任务列表、创建页和后端接口 | Coordinator 默认没有 `tasks.create`，因此空列表没有“新建任务”按钮；任务详情也缺少编辑、重新分配、关闭等管理动作 |
| 地点 | 已有 Location 页面和创建接口 | 入口藏在“更多”，Coordinator 默认只有查看权限，没有创建权限；页面缺少编辑、别名管理、去重合并和新地点审核 |
| 表单 | 已有版本、Section、Field、Option 数据结构 | 新建页只显示基本信息；真正的 Section/题目编辑在保存后的下一页，流程不直观；现有编辑器只覆盖少量配置，不能完整编辑、排序、删除和设置规则 |
| 志愿者采集 | 任务采集页已有动态表单渲染器 | 首页“快速采集”仍进入旧版固定 Activity 表单，管理员 Forms 中的配置不会反映到该页面，形成两套采集系统 |
| 表单答案 | 单选/多选和数字可分别写入结构化数据 | 文本、日期、布尔值等被拼接进一段 qualitative 文本，不能稳定地按字段查询、审核和导出 |
| 自定义配置 | 后端已有多种 Registry | 缺少可操作的配置中心，地点类型、任务类型、表单类型、来源类型、缺失原因等仍无法由管理员在 UI 中管理 |
| 项目与成员 | 后端已有 Program 和 Membership | 缺少完整前台；而创建任务和分配志愿者又依赖项目和项目成员，导致任务链前置条件无法自行维护 |

结论：下一版必须取消“新版任务表单”和“旧版快速采集表单”两条平行链路，统一为一个动态表单定义、一个渲染器和一种字段级答案结构。

## 2. 唯一目标业务流

```text
管理员配置组织、角色和基础选项
  → 建立项目并加入成员
  → 建立/维护标准地点
  → 创建动态表单
  → 添加 Section、题目、题型和选项
  → 预览并发布不可变表单版本
  → Coordinator 创建任务并选择已发布表单版本
  → 分配给项目内志愿者
  → 志愿者看到与管理员预览完全一致的表单
  → 自动保存/离线填写/提交
  → 隐私、安全、完整性检查
  → 人工审核：批准或退回补充
  → 批准记录进入 Records、Insights、Reports 和 Export
```

快速采集也必须进入同一个流程：志愿者先选择一个允许快速采集的已发布表单，再选择或提议地点，然后使用同一个表单渲染器填写。不得再展示硬编码的 Activity 字段。

## 3. 角色与权限

### 3.1 Admin 管理员

- 管理组织级设置、账号、角色和权限。
- 管理所有自定义 Registry 和双语标签。
- 创建、编辑、发布和归档表单。
- 创建、编辑、合并和归档地点。
- 创建项目、维护项目成员。
- 拥有完整审计日志查看权限。

### 3.2 Coordinator 运营协调员

- 创建、编辑、开放、关闭和复制任务。
- 给项目成员分配、取消和重新分配任务。
- 查看所有负责范围内的任务进度和退回原因。
- 创建和维护业务地点；处理志愿者提出的新地点。
- 至少拥有表单查看和预览权限；是否允许编辑/发布表单可由 Admin 配置。
- 进入业务审核队列并退回需补充的提交。

### 3.3 Volunteer / Collector 志愿者或采集员

- 查看自己的任务和状态。
- 开始、继续、拒绝或完成任务。
- 填写任务锁定的表单版本。
- 离线保存、联网同步、上传允许的附件。
- 查看自己的草稿、提交和退回补充项。
- 快速采集时只能使用被允许的已发布表单。
- 可以提议新地点，但不能直接把未审核地点设为标准地点。

### 3.4 Reviewer 审核员

- 查看授权范围内的待审提交。
- 查看按 Section 和题目展示的原始回答。
- 处理隐私、安全、缺失数据和自定义选项问题。
- 批准提交或退回给原采集员补充。
- 所有修改、决定和说明都进入审计日志。

## 4. 功能模块清单

### 4.1 配置中心

必须提供统一的“设置 / 自定义配置”入口，不能要求修改代码或数据库。

- 管理地点类型、任务类型、表单类型、记录来源、缺失原因、项目成员类型、通知类型等。
- 每个配置项支持稳定 Key、中文名称、英文名称、帮助文字、排序和启用/停用。
- 已被历史数据引用的配置项只能归档或发布新版本，不能直接硬删除。
- 支持组织级配置覆盖全局配置。
- 支持选项库复用，例如多个表单共用同一组机构类型、活动类型或服务类型。
- 所有配置变化记录操作者、时间和前后值。

### 4.2 项目与成员

- 创建、编辑、完成和归档项目。
- 设置中英文项目名、说明、所属组织和状态。
- 账号所属学院、系或机构作为 affiliation 资料独立维护。
- 支持创建可复用人员分组；同一人可加入多个组，一个组可包含不同学院或部门的人员。
- 后台可编辑分组名称、说明与成员，并可归档不再使用的分组。
- 添加或移除项目成员，设置项目内角色及有效期。
- 项目成员候选列表可按人员分组筛选，支持全选当前筛选结果后批量添加。
- 任务只能分配给当前项目中的有效成员。
- 在任务创建页发现无可分配人员时，可直接跳转到“添加项目成员”。
- 项目详情显示关联地点、表单、任务、成员和完成情况。

### 4.3 Location 地点管理

#### 标准地点

- Coordinator 和 Admin 都可以从明确入口创建地点。
- 支持名称、地点类型、区域、地址、经纬度、备注和组织归属。
- 支持中英文名称及多个别名。
- 支持编辑、归档和查看引用该地点的任务及记录。
- 创建时按名称、别名、地址和距离提示可能重复项。
- 重复地点可合并，历史任务和记录自动转移到保留地点，并保留合并历史。

#### 志愿者现场地点

- 任务限定地点时，志愿者看到锁定地点，不重复填写。
- 任务未限定地点时，志愿者必须搜索并选择地点，或提交“新地点建议”。
- 新地点建议标为 `unverified`，进入 Coordinator 的地点审核队列。
- 审核时可批准为标准地点、映射到已有地点或合并为别名。

### 4.4 动态表单管理

#### 表单基本信息

- 中文/英文名称和说明。
- 稳定 Key 自动生成，高级用户可修改。
- 表单类型、适用项目、记录来源、是否允许快速采集。
- 草稿、已发布、已归档状态。
- 表单列表显示当前版本、状态、题目数、Section 数和被多少任务使用。

#### Section 管理

- 新增、编辑、删除、复制和拖拽排序 Section。
- Section 支持中英文标题、说明/提示文字。
- 可把题目移动到其他 Section。
- 可选择每个 Section 是否单独显示为一个步骤。
- 删除前提示受影响题目；已发布版本不可修改。

#### 题目管理

- 新增、编辑、复制、删除、移动和拖拽排序题目。
- 每题支持中文/英文标题、帮助文字、占位文字、必填开关和稳定字段 Key。
- P0 必须支持以下题型：
  - Short answer 短文本
  - Long answer 长文本
  - Number 数字
  - Single choice 单选
  - Multiple choice 多选
  - Yes / No 是非题
  - Date / Date time 日期或日期时间
- P1 增加：评分量表、下拉选择、地点选择、照片、音频和文件上传、仅说明文字。
- 文本支持最短/最长长度；数字支持最小值、最大值和整数限制；日期支持范围限制。
- 可启用“未记录原因”；启用后，志愿者可选择配置中心定义的原因而不是伪造空值。
- 选择题可启用“其他”，填写的自定义答案进入映射审核。
- 单选、多选和下拉题支持新增、编辑、删除/归档和拖拽排序选项。
- 发布前校验：选择题必须至少有有效选项、Key 不重复、必填规则有效、条件逻辑没有断链。

#### 条件与逻辑

- P1 支持按前一题答案显示/隐藏题目或 Section。
- 支持跳转到指定 Section 和结束表单。
- 条件引用稳定字段 Key 和选项 Key，不引用显示文字。
- 表单编辑器需要检测循环跳转和已删除引用。

#### 预览、发布和版本

- 编辑器预览必须直接复用志愿者端的同一个渲染组件。
- 可切换中文/英文、桌面/手机以及示例回答预览。
- 发布后版本完全只读；修改必须复制为新草稿版本。
- 已创建任务继续锁定原发布版本，不因新版本发布而改变。
- 新建任务默认选择最新发布版本，也允许有权限的用户选择旧版本。
- 可查看版本差异、发布说明和每个版本的使用任务数。

### 4.5 Task 任务管理

#### 创建任务

- Coordinator 的任务页和首页必须始终显示“新建任务”。
- 创建流程依次选择：项目 → 已发布表单版本 → 地点 → 时间 → 负责人。
- 必填：任务标题、项目、任务类型、已发布表单版本、至少一名负责人。
- 可选：地点、说明、优先级、开放时间、截止时间、关闭时间。
- 地点下拉旁提供“新建地点”；没有发布表单时提供“创建/发布表单”指引。
- 负责人只显示所选项目的有效成员。
- 创建后可保存草稿或立即开放。

#### 管理任务

- 状态：草稿、开放、关闭、取消、归档。
- 分配状态：已分配、进行中、已完成、已拒绝、已取消。
- Coordinator 可编辑未开放任务；开放后不可更换被锁定的表单版本。
- 支持新增负责人、取消分配、处理拒绝原因和重新分配。
- 支持复制任务，保留表单、地点和说明，重新选择日期与人员。
- 任务详情显示各负责人状态、提交记录、退回补充状态和最后活动时间。
- 关闭任务前提示仍未完成的分配。
- 列表支持按状态、项目、表单、地点、负责人、日期和关键词筛选。
- 所有中文界面状态必须完整翻译，不能出现 `assigned`、`open` 等裸英文 Key。

### 4.6 志愿者采集

#### 任务采集

- 首页显示当前任务、接下来任务、截止时间和同步状态。
- 任务详情显示地点、说明、锁定表单版本和负责人。
- 开始后进入与 Admin 预览完全一致的动态表单。
- 每个 Section 可作为一步，显示进度、上一步和下一步。
- 正确渲染所有题型、选项、必填、未记录原因、“其他”答案和条件逻辑。
- 回顾页显示每道题的实际答案，并可点击返回对应 Section 修改。
- 提交成功后显示记录编号、同步状态和后续审核说明。

#### 草稿、离线与纠错

- 输入后自动保存本机草稿；联网时同步服务器草稿。
- 重复提交使用幂等 Key，不能生成重复记录。
- 离线状态、待同步、同步失败和已同步必须明确显示。
- 退回补充后原采集员在首页收到提醒，打开原记录修订并重新提交。
- 表单版本、任务、地点和原始提交关系必须一直保留。

#### 快速采集

- 移除旧版固定 Activity 表单入口。
- 先选择一个允许快速采集的已发布表单。
- 再选择项目（如需要）、地点和记录来源。
- 随后使用与任务采集相同的表单渲染器、草稿、离线和提交逻辑。
- 快速采集记录标记为“未分配采集”，但后续审核和数据结构与任务记录一致。

### 4.7 字段级答案数据

- 每个答案必须保存为 `表单版本 + Section + 字段 Key + 字段类型 + 原始值`，不能把不同文本题拼成一段 qualitative 文本。
- 单选保存选项 Key；多选保存选项 Key 数组；数字保存数值；布尔保存布尔值；日期保存标准时间；文本保存原文。
- “未记录原因”和“其他答案”作为独立结构化属性保存。
- 审核、记录详情、分析和导出都从同一字段级答案结构读取。
- 历史表单标签变化时，记录仍按提交时的表单版本显示。
- 导出同时提供稳定字段 Key 和提交时的中英文标签。

### 4.8 Review 审核闭环

- 统一队列显示记录、隐私标记、安全标记、AI 建议和自定义选项映射。
- 审核详情按原表单 Section 和题目顺序显示问题与答案。
- 显示任务、采集员、项目、地点、表单版本、提交时间和附件。
- 审核员可以批准或退回补充；退回必须填写原因并可指向具体题目。
- 采集员修订后生成新记录版本，旧版本不可覆盖。
- 只有通过隐私检查并人工批准的记录才能进入分析、报告和受控导出。
- 审核决定、字段修订、映射和再提交全部留痕。

### 4.9 Records 记录

- 个人用户查看自己的草稿、待同步、待审核、需补充、已批准和被拒记录。
- Staff 按权限查看组织或项目范围内的记录。
- 详情按表单结构显示字段级答案、附件、地点、任务和版本历史。
- 支持按项目、地点、表单版本、来源、状态、采集员和日期筛选。
- “需补充”记录提供明确的修订入口，不只显示状态。
- 下载和分享遵循数据分类、脱敏和访问范围。

### 4.10 通知、洞察与审计

- 任务分配、临近截止、被拒绝/重新分配、审核退回和审核通过产生站内通知。
- 首页和导航显示未读数量，通知可直接跳转到相关任务或记录。
- Insights、Reports 和 Export 默认只使用已批准记录。
- 指标和导出可按项目、地点、表单版本、字段、来源和时间筛选。
- 系统记录表单发布、权限变化、地点合并、任务变更、提交和审核决定的审计日志。

### 4.11 Dataset 第一阶段（演示基线）

- Records 支持按时间、Program、Location、Form Version、Collector、状态、
  Research Use、Service、Population、Finding Type 和 Theme/Concern 筛选。
- Records 是主筛选入口；记录查看者不因缺少 `datasets.create` 而失去
  筛选能力。列表、当前结果全选、Dataset 冻结和后续报告必须使用同一
  份筛选结果定义。
- 可从标准筛选、当前符合条件的结果或手动选择的记录创建 Dataset。
- 普通 `approved_evidence` Dataset 只接收已人工批准、隐私已清除/脱敏、允许
  Research Use 且在当前权限范围内的记录。
- Dataset Version 冻结精确的 Record Version；刷新创建新版本，不覆盖旧版本。
- Dataset 可将图片、音频、视频与文件附件清单纳入字段策略和内容哈希；详情页支持
  受控预览、播放与下载。图片只有在人工确认隐私审查后才可进入多模态 AI 上下文，
  音频、视频和文件在配置独立转写/解析工作流前不会发送给当前模型。
- 字段策略、PII 权限、CSV/JSON 下载、版本号、记录数量和内容哈希均保留并校验。
- 关键词、隐私状态、关注点等非标准条件冻结当前 Record ID，不伪装成可重复筛选。
- 保留 Insights/Analytics → Records 的既有跳转参数，并接入 Dataset 创建流程。

完整关系和明日演示步骤见
[dataset-phase-1-demo.md](dataset-phase-1-demo.md)。

Dataset 详情/分享/撤销/归档及 Dataset → 初始报告已纳入当前实现；商业评级
与 Local → S3 迁移流程见

## 5. 信息架构

### Staff 桌面端主导航

1. 首页
2. 任务
3. 审核
4. 记录
5. 表单
6. 洞察
7. 更多：项目、地点、人员与账号、配置中心、数据与共享、报告、审计

Location 和 Program 是创建任务的前置数据。即使保留在“更多”，任务创建页也必须提供显眼的快捷创建和管理入口。

### Volunteer 手机端主导航

1. 今天
2. 我的任务
3. 我的记录/草稿
4. 更多

快速采集作为首页动作存在，但必须由权限和表单配置控制。

## 6. 开发优先级

### P0：先修通业务闭环

1. 修正 Coordinator 默认权限：可创建和管理任务，可创建和维护地点。
2. 提供最小可用配置中心：地点类型、任务类型、表单类型、记录来源和缺失原因可由 Admin 管理。
3. 提供 Program 与 Membership 的可用前台，解除任务创建的前置阻塞。
4. 合并两套采集链路；快速采集改用动态表单引擎。
5. 完成表单编辑器的 Section、题目、题型、选项、编辑、删除和排序。
6. Admin 预览与 Volunteer 填写复用同一个渲染器。
7. 建立通用字段级答案结构并改造提交、审核、记录和导出读取逻辑。
8. 完成任务创建、分配、进度管理、关闭和重新分配。
9. 完成 Location 创建、编辑、现场提议、去重和审核映射。
10. 完成审核退回 → 志愿者补充 → 重新提交闭环。
11. 删除或迁移所有会绕回旧 Activity 表单的 UI 入口。

### P1：提高可配置性和运营效率

- 扩展配置中心：组织级覆盖、配置版本比较和跨表单选项库复用。
- 表单校验、缺失原因、“其他”、条件显示和跳转逻辑。
- 任务复制、批量分配、提醒和高级筛选。
- 表单版本差异、使用情况和发布说明。
- 新地点建议审核、别名与合并操作。
- 字段级分析和标准化导出。

### P2：高级能力

- 可复用 Section/题目模板库。
- 表单导入导出和跨项目复制。
- 复杂评分公式与计算字段。
- 多阶段任务和周期性任务。
- 地图视图、路线与地理围栏。
- 更细粒度的组织级品牌、语言和流程配置。

## 7. P0 验收标准

以下场景必须一次完整通过，才算“高度自定义化管理”成立：

1. Admin 新建一个 Location 类型和 Task 类型。
2. Coordinator 新建项目、加入一名 Volunteer、创建一个标准 Location。
3. Admin 创建表单，加入两个 Section，并加入短文本、数字、单选和多选题及自定义选项。
4. Admin 使用真实采集渲染器预览，发布 v1。
5. Coordinator 创建任务，选择该项目、Location、表单 v1 和 Volunteer，并立即开放。
6. Volunteer 在任务页看到任务，进入后看到与 Admin 预览相同的 Section、题型和选项。
7. Volunteer 离线填写一部分，重新打开仍保留；联网后继续并提交。
8. Reviewer 按原 Section 和题目看到全部字段级答案，退回其中一道题补充。
9. Volunteer 收到通知，修改该题并重新提交。
10. Reviewer 批准后，Records、Insights 和 Export 都显示同一表单版本和同一组结构化答案。
11. Admin 发布表单 v2 后，原任务和历史记录仍显示 v1；新任务可选择 v2。
12. Volunteer 使用“快速采集”时选择同一个已发布表单，看到的渲染结果与任务采集一致。

任何一步需要改数据库、手输 URL、切换到旧页面或由开发者代替业务用户操作，都视为未通过。
