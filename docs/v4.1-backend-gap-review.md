## Hardcode classification

Allowed code-owned values are platform invariants: permission keys, public error
codes, HTTP representations, security limits, and lifecycle state machines.
They are versioned and seeded through migrations.

Data-owned values include programs, service/source types, task types, form
fields/options, locations/aliases, organization labels, report layouts, AI
provider/model selection, export field profiles, and translations. New logic
must query their registry or versioned row and must not branch on display labels.

## Delivery order

1. Add constrained and indexed storage models without deleting legacy tables.
2. Extend actor state, scoped authorization, typed errors, and atomic audit.
3. Implement programs, memberships, tasks, assignments, locations, and
   notifications.
4. Implement editable report snapshots and section-scoped AI suggestions.
5. Implement immutable datasets, downloads, shares, revocation, and access logs.
6. Publish shared DTOs/OpenAPI and add migration, authorization, transition,
   idempotency, and concurrency verification.
